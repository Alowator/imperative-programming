## Общие требования

### Код проекта включает в себя несколько файлов исходного кода и заголовочных файлов

```java
huffman/
├── src/
│   ├── main.c       # точка входа и парсинг аргументов
│   ├── io.c         # чтение/запись файлов, работа с каталогами
│   ├── io.h
│   ├── tree.c       # построение и управление деревом Хаффмана
│   ├── tree.h
│   ├── encode.c     # генерация кодов, упаковка битового потока
│   ├── encode.h
│   ├── archive.c    # формат архива: заголовок, индекс, позиции
│   ├── archive.h
│   ├── progress.c   # отображение прогресса обработки
│   ├── progress.h
│   └── utils.c      # общие утилиты (строки, ошибки, память)
│   └── utils.h
├── Makefile
└── README.md !!! README обязательно !!!
```

### Программа корректно обрабатывает ошибочные ситуации, не падает

```java
const char *filename = "data.txt";
FILE *fp = fopen(filename, "r");

if (fp == NULL) {
    fprintf(stderr, "Ошибка при открытии файла '%s': %s\n",
            filename, strerror(errno)); // errno = *__errno_location()
 		// или perror("Ошибка при открытии файла");
    exit(EXIT_FAILURE);
}
```

### Управление программой осуществляется через аргументы командной
строки

Используем getopt.h: getopt(argc, argv, “…”)

### Программа корректно управляет памятью, в частности отсутствуют
утечки памяти

Используем valgrind. valgrind работает как виртуальная машина и перехватывает необходимые вызовы (например, malloc из glibc)

## Требования к архиватору Хаффмана

### Есть отображение прогресса в процессе построения алфавита и непосредственно кодирования

```java
printf("\r["); ... fflush(stdout);
```

### Архиватор поддерживает сжатие нескольких файлов

```java
[Заголовок архива]
[Количество файлов (uint32_t)]
[Индекс файлов — N записей]:
    [Длина имени (uint16_t)] [Имя файла (utf-8)] [Offset (uint64_t)] [Compressed size (uint64_t)] [Original size (uint64_t)]
[Данные файла 1 (сжатые байты)]
[Данные файла 2 (сжатые байты)]
...
[Данные файла N]
```

### Архиватор поддерживает сжатие папки

- флаг -r иначе выдаем ошибку, что это директория, а не файл

на самом деле, если вы научились сжимать несколько файлов, то вы почти научились сжимать директорию, достаточно обойти директорию через opendir(), readdir() (**dirent.h**), необходимо только различать тип объекта (файл или директория)

### Архиватор поддерживает кодирование с алфавитом разной ширины
(1 или 2 байта)

что-то в духе

```java
#ifndef ALPHABET_TYPE
#error "ALPHABET_TYPE must be defined"
#endif

typedef ALPHABET_TYPE symbol_t; // uint8_t или uint16_t
```

## Требования к интерпретатору языка Лисп

### По умолчанию в интерпретаторе реализована мемоизация

Используем мап для каждой функции

### Интерпретатор позволяет расширять возможности языка с помощью
динамических библиотек

На самом деле, достаточно передать управление динамической библиотеке 1 раз, чтобы она зарегистрировала в окружении нужные функции, пример плагина:

```java
#include <stdio.h>
#include "plugin_api.h"

LispValue *builtin_square(LispEnv *env, LispValue *args) {
    if (args->count != 1) return error("square: needs 1 argument");
    LispValue *x = args->items[0];
    return number(x->number * x->number);
}

void lisp_plugin_init(LispEnv *env) { // API
    env_define_builtin(env, "square", builtin_square);
}
```
