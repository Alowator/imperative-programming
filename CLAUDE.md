# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Что это за репозиторий

Материалы для проведения семинаров по курсу **«Императивное программирование»** (язык C + алгоритмы и структуры данных) для студентов первого курса бакалавриата CS.

Курс состоит из двух семестров:
- **I семестр** — задачи на один файл, язык C, базовые алгоритмы
- **II семестр** — командная строка, много файлов, библиотеки, линковка, алгоритмы на графах, ДП

Практические задачи сдаются в системе тестирования **nsuts**, затем — семинаристу лично.

## Структура файлов

```
Семинар N - <тема>.md          # I семестр (номера 0–15)
Семинар XN - <тема>.md         # II семестр (номера X0–XX)
lectures/lecture N*.md         # Лекции I семестра
lectures/lectureXN*.md         # Лекции II семестра
```

**Нумерация семинаров и лекций не совпадает** — семинары идут по своей нумерации относительно лекций.

## Формат семинарного файла

Каждый файл — это **план повествования** для семинариста, а не учебный материал для студентов. Длинные пояснения и определения здесь не нужны — они уже есть в лекции. Файл нужен как опорный конспект на занятии.

Эталон формата — `Семинар X9 - Сжатие данных.md`.

### Структура

- Заголовок `# Семинар N - <тема>` (совпадает с именем файла)
- Разделы через `## <подтема>` — обычно 3–5 блоков по основным понятиям лекции
- Внутри раздела — чередование **Вопросов** студентам и **Задач** на разбор
- Последний раздел часто — «связь с реальным миром»: как простые приёмы из лекции используются в известных форматах/системах
- Завершение файла — короткая **Мысль** с культурно-исторической перспективой («X используется в каждом файле, который вы открываете»)
- Большой семинар может делиться на `# 1 половина` / `# 2 половина` (по 45 минут)

### Маркеры (жирным шрифтом в начале строки, с двоеточием)

- **Вопрос**: — наводящий вопрос студентам. **Ответ почти всегда в скобках после вопроса** (краткая подсказка для семинариста, не для чтения студентам)
- **Задача**: — задача на разбор у доски или в парах (алгоритм / доказательство / разбор)
- **Задача (код)**: — задача, требующая написать код
- **Рисуем**: — нарисовать что-то на доске (дерево, граф, память)
- **Определение**: — короткая формулировка (одна строка, не пересказ лекции)
- **Идея**: / **Мысль**: — ключевая интуиция перед задачей или в конце раздела
- **Алгоритм** (на доске): — пошаговый план для разбора (нумерованный список)
- **Пример** <чего>: — конкретный разбор с цифрами (см. «Пример сжатия ABRACADABRA» в X9)
- **Где применяется**: — практический контекст в конце раздела

### Стилистика

- **Краткость важнее полноты**: минимум текста, максимум вопросов и задач. Семинарист знает тему — файл нужен как шпаргалка по порядку тем.
- **Вопросы ведут разбор**: типичный паттерн — вопрос → короткий ответ в скобках → следующий вопрос углубляет. Если ответ неочевиден, но принципиален — обязательно в скобках.
- **Задачи по возрастанию сложности**: сначала «на доске» / «по шагам», потом «написать код», потом повышенной сложности
- **Конкретные примеры с цифрами**: когда разбираем алгоритм — показать «Было: X бит. Стало: Y бит» на маленьком входе вида 10–15 элементов
- **Контрпримеры ценны**: показать, как «наивное» решение ломается (см. пример с неоднозначным декодированием в X9)
- **Блоки кода** используются для: неоднозначных примеров, ASCII-деревьев/графов, битовых последовательностей, опорных кусков кода. Не для готовых решений.
- **Списки `- **Название**: описание`** — для финальных перечислений приёмов / применений / связанных понятий

### Чего избегать

- Длинных абзацев пересказа лекции
- Готовых решений задач целиком (только опорные куски кода)
- Списков определений без вопросов/задач
- Эмодзи
- Термина «псевдополиномиальная сложность» и связанных формулировок про «зависит от значения числа, а не от его длины в битах»

## Финальный проект (II семестр)

Студенты реализуют **архиватор Хаффмана** на C. Требования:
- Несколько `.c`/`.h` файлов + `Makefile` + `README.md`
- Аргументы командной строки через `getopt`
- Корректная обработка ошибок (не падает на плохом вводе)
- Отсутствие утечек памяти (проверяется через `valgrind`)
- Отображение прогресса обработки

## Связанные файлы в лекциях

Лекции в `lectures/` — это теоретическая база, которую семинары закрепляют практикой. При работе с семинаром N стоит смотреть лекцию с похожей темой (по названию), а не по номеру.
