================== Вещественные числа =====================

Мы уже рассматривали как в компьютере представляются целые числа.
Как задавать вещественные?

> Никак, обходиться только целыми.
Не везде вещественные числа вообще нужны.
Например, в прошивке роутера они вроде незачем, и процессоры для роутеров обычно не имеют аппаратной поддержки вещ. чисел.
> 

> Записывать рациональные дроби: x = p / q (храним целые числа p и q).
Можно делать арифметические операции, например: p/q + a/b = (pb + aq) / (q*b)
Нужно уметь сокращать дроби.абсолютно точные вычисленияв общем случае знаменатель быстро растёт.нельзя представить нерациональные числа
> 

> Использовать вещественные числа с фиксированной точкой (fixed point):
x = z / 10^k или x = z / 2^k
Храним только целое число z, а показатель k — фиксированная константа.
Например (k == 4): x = 13.1735 = 131735 / 10^4
Операции выполняются легко:
(a / 2^k) + (b / 2^k) = (a + b) / 2^k
(a / 2^k) * (b / 2^k) = (a * b / 2^k) / 2^k например ab = (((int64_t)a) * b) >> 16;
(a / 2^k) / (b / 2^k) = (a * 2^k / b) / 2^k например ab = (((int64_t)a) << 16) / b;
При умножении и делении происходит ошибка округления.
> 

Примеры:
* финансы (VB6, тип Currency):
x = (z / 100) — z в копейках, x в рублях; ошибки округления делать нельзя!
* компонента цвета = [0..1]:
x = (z / 255) (8 бит) (правда тут знаменатель — НЕ степень двойки)
x = (z / 65535) (16 бит)
* Doom (1993):
на многих компьютерах не было аппаратной поддержки float-ов, так что использовалась fixed point математика
формат 16.16: x = z / 2^16 z - 32-битное целое

Проблема: если хорошая точность, то плохой диапазон значений (в формате 16.16 числа не больше 65536)
Если увеличить диапазон значений, то теряется точность.
В каждом приложении свои требования на диапазон/точность — нет универсальности.

Как быть физикам с их константами вроде G = 6.67408 * 10^-11 ?
Никаких чисел с фиксированной точкой им не хватит.

> Числа с плавающей точкой (floating point):
x = z * 2^k
Храним оба числа:
z (целое) — мантисса (mantissa)
k (целое) — порядок/экспонента (exponent)
Пример:
x = 1735 * 10^-11 z = 1735, k = -11
> 

Пусть числа имеют размер (a + b + 2) битов, при этом мантисса занимает (a + 1) битов, а порядок (b + 1) битов.
Тогда:
z = -2^a .. 2^a, k = -2^b .. 2^b;
Удобнее будет перевести мантиссу z в вещественное число от -1 до 1 с фиксированной точкой:
x = (z / 2^a) * 2^k
Пример (десятичный):
x = 0.1735 * 10^-7 = 0.1735e-7 (a = 4)

Пусть F — множество вещественных чисел, точно представимых в программе.
Очевидно, множество F конечное (не более 2^s элементов для s-битного вещественного числа).
Для разных схем множество F получается разным:
fixed point: F — равномерная сетка с 2^s числами с центром в начале координат
floating point: F — наложение нескольких равномерных сеток (при каждом k = fixed получается равномерная сетка)

Если посмотреть внимательно на F для floating point:
1) множество F покрывает большой диапазон, сгущается к нулю и разреживается при удалении от нуля
2) вблизи числа x in R представимые числа идут с шагом примерно |x| / 2^a (если в мантиссе a+1 бит)
В результате практически любое вещественное число можно представить с ОТНОСИТЕЛЬНОЙ ПОГРЕШНОСТЬЮ порядка eps = (1 / 2^a).

Погрешность представления вещественного числа получается:
fixed point: абсолютная погрешность 1 / 2^k, где k — кол-во битов после точки
floating point: ОТНОСИТЕЛЬНАЯ погрешность 1 / 2^a, где a — кол-во битов в мантиссе

================ Числа с плавающей точкой IEEE =================

Язык C не определяет схему работы вещественных чисел.
Однако почти все устройства реализуют вещественные числа согласно стандарту IEEE-754 (1985 год).

В стандарте есть типы данных:
float (32-бит) — число одинарной точности (есть в C и в процессорах x86 — популярны в мультимедиа, графике, играх)
double (64-бит) — число двойной точности (есть в C и в процессорах x86 — используются по умолчанию)
Редко встречающиеся типы:
half (16-бит) — число половинной точности (используется в графике и машинном обучении, есть в GPU)
quadruple (128-бит) — число четверной точности (используется в научных вычислениях — поддерживается в современном Fortran)

Отличия представления IEEE от рассмотренного выше:
1) Знак записывается явно отдельным битом, все целые числа в составе беззнаковые.
2) Мантисса нормализованная, старший бит смещён до точки и не хранится (неявно равен 1).
3) Порядок хранится смещённым на какое-то число (например на 127).

Подробнее о пункте 2:
0.00745 * 10^15 — мантисса не нормализована: можно представить это число с меньшим порядком
7.45000 * 10^12 — мантисса нормализованная, лежит в диапазоне [1..10)
В двоичном виде нормализованное число:
1.010110110111011010 * 2^-37
 хранимые цифры /
До точки всегда стоит цифра 1 — можно её НЕ хранить.

Представление float (32 бита):

+—————– знак s: 0 — положительное, 1 — отрицательное
| +————- порядок p (со смещением на 127)
| | +—– знаки мантиссы после точки (M)
| | |
+++–+—–+-+———————+
|s|exponent|mantissadigitsafterdott|
+-+——–+———————–+
|1| 8 бит | 23 бита |

Значение:
x = +/- 1.M * 2^(p-127)
x = (-1)^s * (1 + M / 2^23) * 2^(p-127)

Примеры:

1. x = 1.0f:
s = 0 (положительное)
p = 127 (порядок = 0)
M = 000…0 (мантисса 1.000…0)
Представление:
0|01111111|00000000000000000000000 = 0x3F800000
2. x = -10.0f = - (1 + 1/4) * 2^3:
s = 1 (отрицательное)
p = 130 (порядок = 3)
M = 0100…0 (мантисса 1.0100…0)
Представление:
1|10000010|01000000000000000000000 = 0xС1200000
3. x = 0.1f = (1 + 3/5) * 2^-4:
s = 0 (положительное)
p = 123 (порядок = -4)
M = 100110011001100110011001100110011… (мантисса 1.100110011..)
Представление:
0|01111011|10011001100110011001101 = 0x3DCCCCCD
Заметим, что 3/5 в двоичной системе задаётся периодической дробью — точно представить нельзя.
При печати можно увидеть 0.1000000015 или 0.0999999940.

Вопрос: как записать ноль?!
У числа p есть выделенные значения 0 и 255 — их нельзя использовать в обычных числах.
Они используются для специальных случаев.
Если M и p полностью нулевые, то число считается равным нулю:
0x00000000 (s = 0) — x = +0 (плюс ноль)
0x80000000 (s = 1) — x = -0 (минус ноль)
Получается, что ноль знаковый, и представляется двумя способами.
При этом в обычных операциях и сравнениях оба нуля ведут себя одинаково, и даже считаются равными друг другу.

Кроме того, при значениях p = 0 и p = 255 есть следующие специальные случаи:
+inf и -inf — бесконечности; например:
max_double + max_double = +inf
1.0 / 0.0 = inf
1.0 / -0.0 = -inf
NaN — не-число (not-a-number); например:
+inf + (-inf) = NaN
0.0 / 0.0 = NaN
sqrt(-1e-300) = NaN
acos(1.0000000…01) = NaN
денормализованные числа — специальные числа, которые ещё меньше, чем минимально представимое обычное число
Забавные факты:
любая арифм. операция над NaN выдаёт NaN => появившись однажды, NaN распространяется по всем данным
любое сравнение NaN с чем-либо выдаёт false, в том число NaN не равен и не не-равен самому себе

Тип double: всё аналогично.
x = (-1)^s * (1 + M / 2^52) * 2^(p-1023)
Порядок занимает 11 бит, хранится 52 знака мантиссы.

Диапазон и точность типов (примерно):
float:
диапазон: 2^-126 .. 2^127 = 10^-37 .. 10^37
отн. точность: 2^-23 = 10^-7
double:
диапазон: 2^-1022 .. 2^1023 = 10^-307 .. 10^307
отн. точность: 2^-52 = 10^-16

Машинная точность (machine epsilon) — минимальное eps > 0, такое что 1 + eps > 1.
Иными словами, это примерно расстояние от 1 до следующего представимого числа.
Это число определяет относительную точность представления чисел:
float : eps = 2^-23 ~= 10^-7
double: eps = 2^-52 ~= 10^-16
Также иногда применяют термин ULP (unit in last place) для обозначения ошибки в последнем знаке мантиссы — это примерно то же самое.

================== Операции над float/double ===================

Пусть rho: R -> F — функция округления.
Для каждого вещественного числа она возвращает представимое число, в которое оно превратится при сохранении в программе.
Обычно rho(x) возвращает БЛИЖАЙШЕЕ к x представимое число (round-to-nearest).
В крайне редких приложениях можно поменять режим округления — округлять вниз/вверх до ближайшего представимого.

Будем обозначать операцию в программе, окружая её скобками (без скобок — точная математическая операция).
Операция (+) работает с идеально возможной точностью, если:
x (+) y = rho(x + y) — то есть как будто посчитали сумму идеально точно, потом округлили до ближайшего представимого
Погрешность при этом может быть, но она минимально возможная.
Если для операции это верно, то операция называется точно-округлённой (exactly rounded).
Заметим, что такая операция однозначно определена: на любой аппаратуре она выдаёт бит-в-бит одинаковые результаты.

Согласно стандарту IEEE, следующие арифметические операции должны быть точно-округлёнными:
add, sub, mul, div, sqrt
Это требование выдвигается потому, что есть эффективные алгоритмы реализации этих операций в точно-округлённом виде.
Это в частности означает, что программа с такими операциями работает абсолютно одинаково на всех системах/машинах.

Для сложных операций (в основном трансцендентных) такого требования НЕТ:
exp, log, sin, cos, atan, …
Выполнять эти операции в точно-округлённом виде скорее всего невозможно на практике.
Обычно для них гарантируется, что ошибка не превышает 2 ULP или что-то подобное — то есть относительная погрешность не больше 2 eps или вроде того.
В результате программа с использованием этих функций может работать по-разному на разных машинах и системах — теряется детерминизм.
Во многих процессорах поддержки этих операций нет вообще — они реализаются в C runtime library (через таблицы и ряды Тейлора).

Важно: каждая конкретная операция над вещественными числами выдаёт результат с некоторой относительной погрешностью порядка machine epsilon.
Правда это не означает, что конечный результат вычислений будет иметь относительную погрешность порядка machine epsilon.
Часто в программе неточность возникает, к примеру, при вычитании двух близких чисел:
double x = 1.0 - cos(1e-6);
printf(“%0.15g”, x); //печатает рез-т : 5.00044450291171e-13
//точное значение: 4.99999999999958e-13 (упражнение: можно легко получить это число через ряд Тейлора)
Это явление называется “catastrophic cancellation”.

Кто выполняет операции над вещественными числами физически?
В случае архитектуры x86:
1) x87 = FPU — математический сопроцессор
Для процессоров 8086, 80286, 80386 его надо было приобретать отдельно — в основном процессоре поддержки float не было (поэтому Doom не использовал float).
Начиная с 80486 (1989) или Pentium (1993) FPU стал неотъемлемой частью процессора.
Важно: промежуточные результаты хранятся в расширенной точности (80-битные числа) !
В результате для программиста на языке C по факту детерминизм арифметических инструкций потерян.
Эта проблема преследует нас до сих пор.
2) SSE/SSE2 — новые инструкции.
Появились в Pentium 3 (1999) / Pentium 4 (2000), поддерживаются везде с тех пор.
На 64-битной архитектуре используются по умолчанию, даже в 32-битном режиме включены по умолчанию на многих компиляторах.
Работа с float/double полностью согласно стандарту IEEE — никакого ужаса с расширенной точностью.
3) AVX — ещё более новые инструкции.
Появились в Sandy Bridge (2011), пока поддерживаются не повсеместно.
Вещественные числа работают так же, как в SSE.

====================== Хаки с float =====================

Можно работать с битовым представлением float:
union {
float x;
int i;
};

1. x = fabs(x); (взятие по модулю)
Просто сбрасывает старший (знаковый бит):
i &= 0x7FFFFFFF;
2. x = 1 / sqrt(q); (обратный квадратный корень)
Код из Quake 3:
x = q;
i = 0x5F3759DF - (i >> 1); //МАГИЯ: вычисляет грубое приближение к 1/sqrt(q)
x = x * (1.5f - 0.5f * q * x * x); //итерация метода Ньютона-Рафсона: уточняет значение
Магическая часть — сложно объяснить, требует хорошо понимать битовое представление float

================= Метод Ньютона-Рафсона =================

Пусть f(x) — гладкая функция.
z — её ноль, т.е. f(z) = 0.
Допустим мы знаем число c, близкое к z, и нужно найти z.

Построим касательную к графику f(x) в точке c — линейное приближение функции:
L(x) = f(c) + f’(c) (x - c) //ряд Тейлора: выброшены члены второго порядка и выше
Вблизи c функции f(x) и L(x) должны быть полчти одинаковыми.
Найдем ноль функции L(x):
L(x) = 0
f(c) + f’(c) (x - c) = 0
x - c = - f(c) / f’(c)
x = c - f(c) / f’(c) = phi(c)

Будем искать корень так (метод Ньютона-Рафсона):
x[0] = c //начальное приближение
x[1] = phi(x[0])

x[2] = phi(x[1]) //берём линейное приближение относительно текущего приближения, и находим следующее
…
x[k] = phi(x[k-1])

Как оценить погрешность?
Распишем всё через ряд Тейлора в точке z:
f(c) = f(z) + f’(z) (c - z) + O((c-z)^2) = f’(z) (c - z) + O((c-z)^2)
f’(c) = f’(z) + O(c-z)
Если подставить в phi(c):
phi(c) = c - f(c) / f’(c) = c - [ f’(z) (c - z) + O((c-z)^2) ] / [f’(z) + O(c-z)]
phi(c) = c - (c - z) + O((c-z)^2) = z + O((c-z)^2)
Это означает, что (A - некоторая константа, зависящая от функции):
| phi(c) - z | <= A |c - z|^2
Называется квадратичной сходимостью.

Если изначально приближение верно с 1 знаком после десятичной точки (отн. погрешность 1/10),
то на втором шаге будет 2 верных знака, на третьем 4 верных знака, а на пятом все 16 верных знаков.
Важно найти хорошее начальное приближение, а потом точность возрастает очень быстро.

Пример:
f(x) = 1 / x^2 - q (корень z = 1 / sqrt(q))
f’(x) = -2 / x^3
phi(x) = x - (1 / x^2 - q) / (-2 / x^3) = x + (x - q*x^3) / 2 = x*  (3/2 - 1/2 * q * x^2)
Заметим, что это в точности формула, которая использовалась для обратного квадратного корня в quake 3 (выше).
